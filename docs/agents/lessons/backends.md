# Backends and runtimes

Facts specific to the C, LLVM, JVM, Wasm and N-API backends and their runtimes.

Each line is a rule and the reason it exists. Add one when something costs you time that a rule would have saved; delete one when it stops being true.

- **Before building a Wasm fast path, time three hand-edited variants of the emitted kernel (fast path only with the slow path replaced by `unreachable`, both paths, and the old code), and aim to remove the slow path from the loop with a static type rather than guard it with a run-time check.** A never-taken `call_ref` inside a V8 loop cost about 1.1 ns per iteration (2.33 vs 3.46 ns), so a `ref.test` check placed in front of it gained only 3%.
- **When a change to runtime C has no effect, run `nm` on the built artifact before re-reading the logic, and look for a guard macro defined below its first use.** A Node-API path in `process.c` built, loaded and did nothing because the file's own `__has_include` probe defining `NTS_HAVE_NODE_API` sat 200 lines below the `#ifdef`s it guarded, so the preprocessor removed them silently; `nm` showed the new symbol missing and the old `uv_cwd` still called.
- **Before diagnosing a dispatch or vtable defect, check that the callee's `__call` function exists in `program.c` and grep the log for backend (NTS2xxx) refusals, not only lowering (NTS1xxx) ones.** React component calls crashed through null because 8 closures had empty method tables, each because the backend had refused its call body in a cascade, while a census reading only NTS1xxx said nothing was refused and a wrong fix was nearly built.
- **Before a lowering change emits a new runtime helper, tell every other backend's lane the helper names and the single case that turns their gate green, and hold the commit until they catch up rather than lowering a floor.** Optional-property presence bits cost the JVM backend ten examples and a benchmark the moment they landed, and `bench-agree` fails on a single disagreement with no allowance list; a helper missing from `hir::runtime` fails silently (a `uint32_t` widened to a double), and on the JVM a growable array looks up helpers in a second table by stem.
- **When adding an `#include` to `runtime/c/nts_runtime.h`, run `git grep -F nts_runtime.h` and copy the new header at every site that copies the runtime header alone into a temp dir.** Adding `nts_string_view.h` broke four tests and a tool that preprocess the header in isolation, and the error ("file not found") looked like a broken header rather than a missing copy.
- **When building IR by hand, use the op whose name is the operation you mean (such as `UnOp::ToUint32`), not a source idiom assembled from primitives.** A hand-built `>>> 0` lacked the operand coercions the expression path inserts; C's emitter forgave it while LLVM returned `split(",", -1)` one element short.
- **Mark any emitted C struct that is read through another struct's pointer with `NTS_OBJECT_STRUCT` (may_alias), and test a suspected aliasing miscompile in twenty lines of plain C with and without `-fno-strict-aliasing`.** Object structs are emitted flat, so clang's type-based alias analysis carried a constructor's 0 past a write of 200 made through the base-class pointer on stack-allocated objects, while LLVM and the JVM answered correctly.
- **Make internal fields in runtime TypeScript `#name` (or a symbol key when a subclass in another file reads them), never `private` or `protected`.** `private` hides a field only from the type checker; at run time it is an own enumerable key, and three conformance defects (EventEmitter, `fs.Dirent`, http's OutgoingMessage) were extra keys node does not have.
- **Use the vendored QuickJS `libunicode.c` and `libregexp.c` for Unicode and regular expressions in the C runtime, and keep ICU as an opt-in link for genuinely locale-sensitive behaviour.** They are dependency-free MIT-licensed C that drops in beside the runtime and unblocked 89 sites, while ICU4C would put a C++ runtime and a large data file into every binary for zero sites that need it.
- **After editing the Wasm census driver (`tooling/wasm/check-corpus-example.mjs`), run a changed row in Chromium via `tooling/wasm/browser/run.mjs` as well as in node, and guard host-specific calls.** A `setTimeout(...).unref()` passed the node census and turned 15 rows "unmeasured" in the browser census, where `setTimeout` returns a number.
- **Truncate a type reference's arguments to the declaration's arity before looking it up, resolve to every matching record, and reuse `hir::lower::Carried` or `hir::instantiate::Templates` rather than writing another truncation.** tsgo records a class's references to a generic as `Base<T, this>`, one argument more than declared, which caused two separate defects: a derived class inheriting a form with no layout, and an interface method with no implementer.
- **Treat the JVM backend as the oracle for type-confusion bugs: when all backends agree, ask what each one actually checked, and write one function per layout instead of sharing one across layouts with no base relation.** C and LLVM read whatever sits at a field offset and agreed with node by luck on a wrong-typed object, while the JVM threw ClassCastException.
- **Before landing a change to slots, vtables or signatures, run the gate's `jvm-verifies` and `assembles` steps through `pinned.sh` on the candidate, alongside the runtime output inventory.** A C `--napi` inventory and four-backend fixtures passed while a refused virtual entry inherited a program-wide signature instead of its nearest ancestor's: `ZlibBase._read(D)V` could not override `()V`, and the landing gate lost 19 JVM classes. C's calling convention hid the mismatch; the JVM step checked its own prepared program and caught it. The underlying `_read` refusal already existed on the before pin, so compare the same command and options before naming an introducing landing.
- **Before calling a JVM runtime reader wrong, disassemble its caller to see whether the reader's answer is kept, and probe every position a value flows through (declaration, return, argument, property).** A claimed null-versus-undefined bug in array readers was refuted because the lowering re-erases by static type, and the probe found the real gap one step over: array holes from `new Array(n)` in return and argument position.
- **Never derive a semantic relation from Wasm GC structural type equality; relate types by HIR facts and choose control flow by the descriptor, not by `ref.test` between object types.** Two same-shape classes from unrelated hierarchies became one type, so a virtual call ran the other hierarchy's method (11 of 22 wrong), and a `ref.test` fast path read `Swapped { b; a }` in `Pair { a; b }`'s order (-4000 where node says 2000).
- **Before sharing, hoisting or dropping a Wasm string-length test, count the variant: V8 already folds repeated `wasm:js-string` `length` calls, and the `i <u length` guard in front of a checked read is what lets it drop `charCodeAt`'s own bounds check.** Hoisting json-scan's ten per-read `length` calls to one counted the same 184,844 instructions an operation, and removing the guard altogether counted 10.7% more (204,540), so a planned HIR operand for the length would have bought nothing.
- **Keep every call out of a Wasm loop's hot path, even one that never runs: decide before the loop and emit a loop without it, rather than guarding a fallback call inside.** Counted on the strings row (2026-10-20): reading the scanned text from a GC array saved 10.94% of the row, and the same loop with a never-taken fallback `charCodeAt` call beside each read cost 5.86% more than the original -- V8 pays for a call's register pressure every iteration -- which sank a per-function string-units cache that read correctly everywhere.
- **Hand V8 a host builtin in the bound form it recognises, and count each one: V8 calls a fixed list of imports as its own builtins from Wasm, with no JS wrapper, but only in an exact shape and signature.** `Function.prototype.call.bind(Number.prototype.toString)` imported at `(f64) -> externref` became `WasmFloat64ToString` called from the module, and number-format counted 49.5% fewer instructions (57,846 -> 29,187 per op, 2026-10-21) than with the same method behind an arrow, whose wrapper and argument boxing were 39% of the row. The list is narrow: `(i32) -> externref` was not recognised (-0.09%), `String.prototype.indexOf` bound alike was not either and cost the strings row 5.28%, and `toLowerCase` bound cost case-convert 2.8% -- an arrow V8 inlines into a direct builtin call can beat a bound import it does not know.
- **V8 inlines Wasm by function size, and a function's local declarations are part of its size: declare locals in one run per type.** A local section encodes as runs of one type, two bytes or more each. `fib#whole`, with locals `i32 i32 i32 f64 i32 i32 f64 f64 i32 f64` in six runs, was 52 bytes, and V8 gave its recursion an inlining budget of `min(104, 700)` -- "not enough inlining budget" at every call; the same body with its locals in two runs was 44 bytes, under V8's small-function threshold, given `min(220, 7000)`, and inlined three levels deep: `fib` counted 31.5% fewer instructions (12,401,792 -> 8,499,385 per op, 2026-10-20). Found when a compiler change reordered `fib`'s locals and nothing else; `--trace-wasm-inlining` shows each budget and decision. `locals.rs` now groups every program function's locals by type, so a size threshold is never crossed by declaration order.
- **Leave a loop-carrying runtime helper to V8's own inliner; copy only loop-free ones.** Taking map-and-set's table helpers into this backend's inliner (branch `wasm/hot-helpers`, kept as the record, 2026-10-21) made each small loop-free helper free or better -- `Has`, `Set` or `Entry` alone -0.15%, `Set` -> `Put` -0.29% -- but `Find`, a probe loop with an `Equal` call inside, copied under `Has` cost 1.14%, and every helper chain together 2.58%, with loop peeling and unrolling ruled out. The copy mechanism is sound: a loop inside a copied callee is where V8's inlining, with its call counts per site, does better. If helper inlining comes back, its shape is loop-free helpers only, worth about -0.15 to -0.29% on map-and-set.
