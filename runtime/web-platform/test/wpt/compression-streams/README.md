## Execution

`environment.ts` installs the package's canonical CompressionStream and
DecompressionStream through an environment runtime with the test-only
node:zlib provider. No host CompressionStream or DecompressionStream is exposed.
The provider retains all created contexts for cleanup because some upstream
cases finish their assertions without closing their writer.

The package's TextEncoder, Streams, Blob and Fetch implementations are supplied
where the originals use them. A small area-owned HTTP peer serves only the two
hash-verified original media files. The unchanged fixtures request them over
real local TCP using the package's Fetch; both paths must be observed during
every complete run. No fetch stand-in or network result substitution is used.

Genuine implementation-realm ArrayBuffer, typed-array and DataView constructors
are injected to preserve input and output identity. Genuine ECMAScript
WebAssembly.Memory supplies shared-memory rejection inputs. This does not claim
a browser Window, worker or ShadowRealm run. The original Pako helper is retained
only as WPT's independent test oracle; no compression primitive enters package
TypeScript.

## Scope and exclusions

The API implements [Compression Standard §§2–5](https://compression.spec.whatwg.org/)
for `gzip`, `deflate`, `deflate-raw` and `brotli`. Section 3 requires Brotli
compliance with [RFC 7932 §1.4](https://www.rfc-editor.org/rfc/rfc7932#section-1.4).
The existing transform algorithms, runtime hookup and failure-as-value capability
serve all four formats. `windowBits` applies only to DEFLATE and is ignored for
Brotli; the native implementation selects RFC 7932 settings.

Two exact cases remain left out under cloud-agents.md:

- `data should be correctly compressed even if input is detached partway`
- `data should be correctly decompressed even if input is detached partway`

They patch Object.prototype.then and invoke window.postMessage during promise
resolution. The rule forbids that intrinsic patching, and the host/VM adapter
does not provide a shared browser realm. Local package tests retain their
deterministic detached-buffer controls.

`compression/idlharness.https.any.js` is imported and hashed, but its full
generated WebIDLParser/idlharness environment, fetched IDL and browser/global
descriptor exposure are unavailable. It is reported as one not-run file, with
null case counts, and never contributes passing synthetic cases. The remaining
18 executable files run with exact registration counts and stale exclusion
checks. Descriptor-only IDL cases remain outside the cloud-agent scope.

## Existing adapter and native Brotli implementation

The adapter fix already in #109 supplies `assert_less_than` with the semantics of
WPT [`resources/testharness.js` at the shared pin](https://github.com/web-platform-tests/wpt/blob/a8f306ee4399724f33399dfdcac7da296f3cc05a/resources/testharness.js):
primitive numbers or bigints, matching operand types and strict ordering.
Its positive and negative controls remain active. The Brotli change adds no
shared-adapter modification and does not weaken an assertion.

The test-only `node:zlib` provider creates native Brotli compressor/decompressor
handles and retains each across writes. The same bounded-output processing loop
selects Brotli's `BROTLI_OPERATION_PROCESS`, `BROTLI_OPERATION_FLUSH` and
`BROTLI_OPERATION_FINISH` flags. Native format failures are returned as values.
Finish checks the native `Z_BUF_ERROR` code, because Brotli's numerical error
values overlap zlib's values; incomplete input can return its valid prefix
before the shared stream errors. Native allocation and state errors retain
operation-failure classification.

The decoder stops at the first stream end and reports unconsumed input for the
shared trailing-data check. Native Large Window extensions remain disabled:
controls accept RFC 7932 windows and reject a native-generated Large Window
stream. Reset, ownership, output bounds and idempotent cleanup use the existing
capability contract. No Brotli primitive, framing or checksum enters shared
TypeScript. Gzip and DEFLATE keep their native framing and checksum validation.
