# Fixtures and controls

Fixtures, controls, probes, reductions and sabotage: how to make a test that can fail for the reason you think.

Each line is a rule and the reason it exists. Add one when something costs you time that a rule would have saved; delete one when it stops being true.

- **For anything whose job is to avoid work, ask "if this did nothing at all, which test would fail?", add an assertion that counts the work avoided (entries rewritten, processes spawned), and sabotage the mechanism to watch it fail.** A cache-key fix left the snapshot cache never hitting for six hours with every test green, because the tests asserted correctness and a build that recomputes everything is correct; a sweep disabling one optimisation pass at a time found frame placement could be switched off with zero tests noticing.
- **When a verification mechanism checks a boundary, write down whether it compares declarations (shape) or executes the call (value), because it cannot do both.** A witness proving the emitted C prototype matched the real header exactly could not see that the value passed to a function-pointer parameter was a heap closure object rather than code; only a consumer that actually calls it catches that.
- **When adding an `nts.config.ts` to an existing example, build it before and after and compare what crosses the boundary.** A config routes the program through a different set of roots (what the entry publishes), so the same example compiles two ways that nothing compares; the first afternoon surfaced a published class losing its methods and an `invalid HIR` crash, caught only by a checked-in `javap` capture.
- **Extract and compile a fixture's commented-out control program before committing the fixture.** The blockers check runs only the fixture, never the control written as a comment, and a hand sweep found 3 of 20 `lib-dom-*` controls did not even typecheck, two of them labelled "clean" without being run.
- **Probe with the population's real key distribution or real data before calling a mechanism refuted.** A probe inserting keys `0..n` round-tripped identically up to 200,000 entries and "refuted" hash-map iteration order as the cause of an unstable digest, but it was the cause: dense sequential keys never collide, while the real decoder's sparse keys diverged from 20,000 entries on.
- **Give every blocker fixture a case that must stay clean beside the case that refuses, and when a comparison's rows differ in two things, run the missing cell.** The smallest program producing the error text is not the smallest program having the defect: a "narrowed value in an object literal" fixture turned out to be shorthand-only once a control was added, a would-be cascade was really property shorthand, and a three-row comparison blamed the declared type when the returned value was the real cause.
- **Put a fixture whose symptom is a run-time abort, a wrong answer or a backend decline in `examples/`, which runs against node, and when reading `nts check` read the declined, reached and function counts rather than the verdict line.** Blocker fixtures are compiled but never run, so `xs[0] = "ab"` aborting on an empty array satisfied its `expect: nothing refused` on both broken and fixed compilers, while `nts check` filed the abort under "declined" and still printed "agreed on every case" over 16 of 58 cases.
- **When building a generator, translator or binder, point it at the largest real input you can as soon as you can, and never let a test's skip condition share a branch with its result.** A JVM binding generator with 32 green tests failed with 1,479 errors on its first real `android.jar`, from seven bugs each matching a shape the hand-written fixture lacked; separately, a test returning early on an empty result (meant for "no tsgo") passed three sabotage runs because it also swallowed "the generator produced nothing".
- **If a defect is in constant folding, write the fixture with literal operands and no parameters, and run it against the old compiler to confirm it fails there.** Three new arms for the negative-zero underflow fix each took `a: number`, so the value was computed at run time and all three agreed on the buggy compiler; rewritten with literals, two disagreed on the old binary.
- **In a probe for a signal or callback, append every call to a list and assert the whole list, never store only the last value.** A react-gtk `onResponse` probe storing the last response hid that React's own `force_close` also emitted the signal; had the calls come in the other order, the probe would have passed over the bug.
- **When a fixture needs something refused only as a means, use a gap documented as permanent (a `RegExp` field, a regular-expression literal, a stack read) and say in the header that the refusal is manufactured and why.** Three fixtures manufactured their refusal with `Map<any, any>` or an unpinned `any`, and all broke in one night when `any` gained a representation, reading as CHANGED or FIXED exactly like the defect coming back.
- **For every new way of making a call (`.bind`, `.call`/`.apply`, a function made at run time), write a fixture arm whose callee throws for half the inputs inside a `try`, plus one a call deeper, and confirm it fails on main's compiler.** The raising analysis reads the callee's symbol, so a call whose symbol is not the function it reaches silently counts as "cannot raise" and the program aborts with `uncaught` where node catches; `.bind` landed through the full gate with 116 agreeing cases, none of which threw, and `.call` had been broken since it first lowered.
- **Before writing "A rather than B, because of example E", evaluate E under B; if B gives the same answer, find the input where they differ (negative zero, NaN, empty, the boundary of every `<`), run it against node and cite that.** A `toFixed` comment justified reading the sign bit with `(-0.4).toFixed(0)`, which `x < 0` also satisfies; the distinguishing input `-0` showed the sign bit was wrong, and a fuzzer found it the next night.
- **When a blocker fixture names a way to close it, build the smallest measurable version, measure the corpus rather than the fixture, diff diagnostic codes (not totals) against a binary pinned just before, and write the numbers and any reverted experiment back into the fixture.** A structural-`implements` experiment made the fixture pass but cleared zero sites and added two, and a later one-line correct condition turned a refusal into a worse backend decline (NTS2006) that a falling total would have hidden.
- **When probing erased or `unknown` behaviour, give the function two callers of different types, and read `nts hir --prepared` for `erase`/`tag.of` before naming a mechanism.** Lowering narrows an `unknown` parameter to its only caller's type, so a GTK `instanceof` probe called from one site had no erase at all, and the reported cause ("erasing a handle loses its tag") was wrong in both halves.
- **When a test flips with no explaining change, bracket the suspected state (create it, remove it, same build) before bisecting commits.** A child-process test passed only if an earlier run had left `third_party/node/test/.tmp.0` behind, because a forked child loads node's real test helpers and binds a socket in a directory nothing in the run created; the bisect landed on an innocent commit.
- **Before running a probe, ask which arm would be wrong if the defect were present, check the arms differ in exactly one thing, check which pass actually produces the number, and confirm the harness reads what you changed.** One probe passing a single class through a class-valued site agreed 29 of 29 while two classes disagreed on 18; `instanceof` folded to false by an earlier pass made a layout merge look benign; a guard probed with 3.5 tested the wrong conjunct; and nine paired runs compared a harness that never loaded the compiled code.
- **Make any check that builds something only to ask a question build it in a private directory and remove what it wrote, and give a loop that has never had input one input in a sabotage arm before relying on it.** Adding the first name to the addon floor's always-empty BLOCKED list made its probe build `cluster.node` into the shared addon directory, where the load check failed on it and turned the gate red for every lane.
- **Sweep through `tooling/sweep/probe.sh` (which asserts the result) rather than bare `emit-c`, grep the emitted C for the function's name before believing a pass, and for anything that happens at a phase (module init, a constructor) ask what the value would be if the phase never ran.** A ten-line probe "lowered" an unrepresentable `Iterator<T>` parameter because the single-use function was folded away, and a fixture for "did the initialiser run" printed the right answer on the broken compiler because its value was a foldable literal.
- **When a reduction's control fails, diff the reduction against the original line by line and restore the differences one at a time, modifiers included, before deleting it.** A minimal fixture for a lost error `code` failed its control because it had dropped `override`: a property with two modifiers lost its initialiser entirely, a form `internal/errors.ts` writes on 94 classes.
- **Give every optimisation, cache or memoisation a test that counts what it did, and disable the mechanism once to watch that test fail before believing it.** A snapshot cache was dead for six hours beside passing tests, because a build that recomputes everything is still a correct build; disabling dead-code elimination failed only two tests, neither about dead code.
- **Check a stand-in's claim that the host stays quiet until asked against node's source for that method, and give every socket control arm both read and write directions.** node's `socket.pause()` only stops reading for sockets built with `onread`, so a cluster primary lost the first bytes of every connection while a write-only control passed, and adding a `console.error` hid the race entirely.
- **When a lane feels blocked, write about twenty small unrelated questions at one seam and run them against node, one export per child process, counting refusals apart from disagreements.** In four of five such sweeps the questions themselves came back clean and the finding was something else, such as a `try`/`catch` that did not catch what a called function throws.
- **Run derived tests against node's real module (`NTS_CONFORMANCE_ORACLE=1 node tooling/conformance/run-one.mjs <module> <file>`) to find assertions upstream never made.** Four defects survived because our own tests asserted them, for example `emitDestroy() === emitter` where node returns `undefined`, and plain objects where node's have a null prototype.
- **Before writing how far a fix reaches, remove the fix and re-run the sweep, and phrase anything unmeasured as unmeasured.** Three times in one night the cause was right and the claimed scope wrong: "every operation that allocates its result uninitialised" was really `map` and two variants out of thirteen swept shapes.
- **Before choosing a check, ask whether the regression would remove code (count what is present), change it (run and compare) or make it not build (compile the artefact).** A defect that made a function refuse left `nts check` reporting "agreed on every case", and a change that left every refusal count byte-identical emitted C that did not compile.
- **Probe inputs that node handles in one C++ path but nts handles separately at each call site, capturing node's answers first as the oracle.** Buffer paths found 24 fs functions rejecting what node accepts, a variation none of node's 260 fs test files exercises.
- **Before comparing two arms, check that the harness actually reads the variable you changed.** `fuzz-timer-order` runs no compiled code (it never reads `NTS_BIN`) and flakes about 1 run in 6, yet pairs of its runs were read as a compiler regression and then as exoneration before one grep showed the arms could not differ.
- **After a leave-one-out sweep, retire the candidates together in one build before declaring any of them unneeded.** Two React stand-ins each read as unneeded alone, but with both removed the program was refused again on the same gap, because each cut the path to the other's construct.
- **For a test262 census failure, materialise the real case with `tooling/census/materialise262.ts` and reduce from it, not from a typed reconstruction.** Three TypeScript rebuilds of eight failing files all agreed with node because they dropped what mattered: the exact pattern `[[] = init()]` and a function with no `return`.
- **Probe module-scope statements with `tooling/sweep/probe.sh`, writing each construct both at module scope and inside a function and comparing the two verdicts, and after making any rule stricter diff whole-corpus refusal counts against a baseline binary.** `nts check` and the census only drive exported functions, so module-scope defects (a `var` redeclaration leaving 99, a `switch` that panicked the compiler, a `for...of` closure that segfaulted) surfaced only this way, and sixteen passing probes missed a regression that a 314-example count diff caught (note that `NTS_RC=1` does nothing to `probe.sh`).
- **Treat a binding probe that fails to build as the result, and read the consuming TypeScript before writing an expected value.** 195 comparisons across 15 probes found 0 divergences while five real defects (a libc name collision, wrong zlib signatures) surfaced only as build failures, and all seven comparison mismatches were wrong expectations.
- **When a reduction stops reproducing, put back what you removed last, one piece at a time, watching for the step that makes it pass as well as the step that makes it fail.** Several defects key on a whole-program fact (any class with dispatch slots, one optional `port` field anywhere, any closure, a second use of `-1 >>> 4`), so shrinking can delete or even supply the trigger and the fixture stops failing.
- **Run every new fixture against the compiler from before your change; if it passes there too, it did not test the change.** Two 116-case fixtures "agreed on every case" on both binaries, one because the invented shape never produced the type under test while the real corpus shape disagreed with node on 29 of 29.
- **After a mechanical edit across tool scripts, run each changed tool at least once, and write an edit script's checks against the original text.** An edit script decided an import already existed because it matched the comment it had just inserted, and `node --check` passed all six tools that would throw on the undefined name.
- **When a reduction does not reproduce after one try, delete down from the real failing file one change at a time instead of growing a probe from memory.** Two rounds of adding to a hand-written probe never reproduced a dropped module evaluation; three deletions on the real file found it in minutes, because the real file declared `type ConsoleTask = unknown` where the probe had written an interface.
- **When a fixture's expected output orders one event before another, make the order structural by starting the later step from the earlier event (with a bounded wait), and run the fixture at least twice before committing.** Two macOS fixtures whose callback raced a timer passed three or more runs and then failed once on the VM, making main flaky.
- **Sweep ordinary language shapes with tiny one-shape fixtures run through `nts check` against node, reading both the refusal count and the agreement line.** A refusal census only sees code the compiler reached, so `const [, second] = pair` and `super.getter` scored zero sites while being real gaps, and a diagnostics-only probe called two positions clean that answered 2 where node answers 105.
- **Run every control arm against node, on all three backends, before calling it a control.** Controls written to frame a fix (positions believed to already work) turned out to compile silently wrong, answering 2 where node answers 105, and another control found `super()` skipping a base class's field initialisers.
- **Before writing a fixture for an ordinary shape, search `examples/` (with awk) for one that exists, keep only the shapes a sweep finds failing, and ask what all of a feature's fixtures share that is not the feature.** 19 of 20 swept statement shapes already had named fixtures, while enums passed four single-file examples and broke as soon as a module boundary sat between declaration and use.
- **Before building the feature that clears a refusal, write a probe whose answer differs between the candidate implementations and run it against node.** Lowering "a method used as a value" as a closure capturing its receiver built `c.twice.bind(c)`, which answered 30 where node throws, because reading a method off an object does not bind `this`.
- **Give a scratch probe an absolute `extends` to the repo's `tsconfig.fixtures.json`, and when a recorded result contradicts a hand run, suspect the harness's copy of the project first.** Fixture configs extend by relative path, so about thirty copied probes silently compiled on compiler defaults, and the outcomes harness dropped a fixture's `noUncheckedIndexedAccess` and recorded a disagreeing program as agreeing.
- **When a library type is refused, write the same shape by hand and see whether it lowers, and when a probe must hide a fact from the compiler use a parameter, not a local with an initialiser.** A hand-written iterable interface lowered where `Iterable<T>` was refused, turning a planned three-backend feature into six names added to a list that cleared 162 refusal sites.
