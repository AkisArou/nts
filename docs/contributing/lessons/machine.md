# The machine and its tools

Historical `tsgo` commands below are pre-switch (tsgo); the current frontend is in process.

The shell, toolchains, disk, memory pressure and git on this box.

Each line is a rule and the reason it exists. Add one when something costs you time that a rule would have saved; delete one when it stops being true.

- **A private validation unit gets the gate's host environment, not a hand-picked one (2026-10-28).** Start it with `systemdEnvironment()` from `tooling/gate/environment.ts`, which passes the canonical host capabilities (`HOST_CAPABILITIES` in `canonical-environment.ts`: `JAVA_HOME`, `DEBUGINFOD_URLS`, the SDK roots and the rest) into `systemd-run`, and set `NTS_BIN` to the build under test. In one morning three runs lost a cycle to setup: a JVM crate's `javap` tests returned early without `JAVA_HOME`, an interop project could not start Valgrind without `DEBUGINFOD_URLS`, and a sabotage test aborted looking for an unbuilt default `target/release/nts`.
- **Cap each test262 case, bound concurrent frontends, and make long runs resumable.** Before the native switch, a 6 GB address-space cap and at most 8 workers were required: one 65 KB file (`identifiers/start-unicode-16.0.0-escaped.js`) drives tsgo to 7.2 GB, and a 12-worker run triggered a machine-wide out-of-memory kill that took down unrelated sessions too; below 3 GB even trivial cases fail because Go reserves address space up front.
- **Clean whole Cargo artifacts, never selected files inside `build/*/out` while retaining their fingerprints.** The 2026-10-26 partial cache cleanup removed generated `private.rs` files while Cargo still considered their build scripts fresh, breaking the next gate. The tests step now keeps its current executables and prunes obsolete test executables and their `.d` sidecars; libraries, fingerprints and generated output stay together.
- **When comparing a golden file fed by `sort`, `ls`, `find` or glob order, run the comparison once under `LC_ALL=C` too, put `LC_ALL=C` on the `sort` itself in your own tools, and never export it into a gate or test run.** A file listing sorted under `en_US.UTF-8` matched locally four times while the gate, sorting bytewise, moved one block to the end; the other way round, exporting `LC_ALL=C` into a gate turned a Java test printing é and an emoji red because Java encodes output from the locale.
- **Never compare a `&'static str`, `&'static [T]` or anything a `const` produces by pointer identity (`ptr::eq`); use `==` or an enum.** Whether duplicate string data shares one address is the linker's choice, so the release profile (thin LTO, one codegen unit) merged them and the dev profile did not, giving one example 0 refusals in release and 3 in `cargo test`; every instrument was a release build, so only that disagreement revealed it.
- **Canonicalise any path used as a key or handed to something that changes directory, and give code environment facts (via `CARGO_MANIFEST_DIR`, explicit settings) rather than letting it infer them; check tests once with `CARGO_TARGET_DIR` outside the repo.** The snapshot cache keyed on `tsconfig.json` as given, and `Path::parent()` of a relative path is `""`, which disabled the collision guard, so two projects shared one cache entry and `emit-c` silently wrote the other project's program; every test fixture path was absolute, so nothing caught it.
- **When reading C headers with libclang, pass clang's resource directory and treat any error-severity diagnostic as fatal before reading the AST, and never use `-fdump-record-layouts-complete`.** Without the resource directory `size_t` is undefined and libclang error-recovers, reporting `write`'s third parameter as `int`; and the `-complete` layout dump is wrong about every packed struct (`epoll_event` as 16 bytes instead of 12).
- **Queue a gate with `sh tooling/gate/with-lock.sh --wait ...`, not a background `while pgrep -f ...` loop.** `pgrep -f` matches full command lines, including the loop's own shell, so a background "wait until no gate is running" loop never ended and held a lane's gate for about 40 minutes.
- **Bound any probe whose loop may not terminate: put a guard in the source and run it under `(ulimit -v 8000000; timeout 60 …)`.** An allocating infinite loop in a probe killed the whole agent session twice with exit 144 and no transcript, because `timeout` alone did not stop the memory pressure.
- **Before a scripted insertion, read the lines above the anchor (or anchor on the start of the enclosing item), and before wrapping a tool, read its header for how it wants to be called.** A string-anchored insert put a new method between an `#[allow]` attribute and `fn call`, producing the exact clippy error a comment three lines above warned about, and a sweep driver called `wait-idle.sh` before taking the lock, the order that script's own header marks as wrong.
- **When a file must contain `\u` escapes, write it from Python using `chr(92)` for the backslash and assert the file is pure ASCII afterwards.** A ` ` typed in a Bash command, even inside a quoted heredoc, arrived as the raw line separator, which ended a `//` comment and turned a fixture into a syntax error that was recorded as "refused".
- **Print any value a script will parse with `process.stdout.write(String(x))`, never `console.log`.** This shell exports `FORCE_COLOR=3`, so `console.log(0)` printed a coloured `0`, the shell test `[ "$n" -eq 0 ]` failed silently, and a guard reported every empty module as newly publishing.
- **Locate repo resources in tests through `env!("CARGO_MANIFEST_DIR")` or the fixture's own path, and verify a layout-sensitive test with `CARGO_TARGET_DIR` outside the repo.** The gate builds in `~/.cache/nts-gate/target`, so a test that walked up from its fixture to find `third_party/node` passed locally and failed in the gate.
- **When failures are incoherent (an unrelated test failing, `echo` exiting 1, many fixtures "needing a person", noisy measurements), check `/tmp` with `df -h`, `df -i`, `ls | wc -l` and `free` before the code, delete build output as you go, and never delete `/tmp/claude-1000`.** `/tmp` is a 16G tmpfs with an inode cap and a per-user quota, and filling it has shown up as a quota error in an unrelated test, heredocs truncated at 4096 bytes, 31,073 leftover test directories failing nine fixtures, and a 7.5 GB cache pushing the box into swap.
- **Typecheck a project with the pinned frontend before relying on ambient `@types`, or state the dependency with `/// <reference types="node" />`.** In the pre-switch `target/tsgo -p <tsconfig> --noEmit` check, TypeScript 7 defaulted `types` to `[]`, so `@types/node` at the repo root is invisible unless named, and an `import ... from "node:url"` failed with TS2591 in every config project.
- **When a whole category of tests fails at once with a fluctuating count, suspect a shared kernel resource before the last edit; for `fs.watch` ENOSPC failures, run `watchman watch-del-all && watchman shutdown-server`.** Watchman watching node's 15GB test scratch directory inside the repo held about 523,000 of 524,288 inotify watches and failed 24-26 `fs.watch` tests with no code change.
- **Give each worktree its own `CARGO_TARGET_DIR`, delete `debug/incremental` after test runs, and run the backend crates' tests too before gating a core change.** Two worktrees sharing one target reused each other's compiled crates, so a build "finished in 0.03s" and ran the other tree's code, costing forty minutes of doubting a correct fix.
- **Write header- or library-availability probes as a real `-c -o <object>` compile, never `-fsyntax-only`, and give the probe a test arm where it succeeds.** `zig cc`, the cross compiler for every non-host target, fails `-fsyntax-only` with "FileNotFound" at 1:1 whatever the file says, so a libuv probe refused every cross build while both of its tests passed.
- **Run Apple and Windows interop with the machine otherwise quiet, not beside a full gate.** The macOS VM has 4 GB: beside a gate it failed Apple projects that pass alone (18 of 18 on main with nothing else running), which reads as a regression in whatever is being gated.
- **Before queueing Apple interop, boot the VM and confirm its desktop, then let `run-ios.sh --reachable` boot and ready the configured simulator before the application's deadline. Keep its stage diagnostics in the gate log.** Two cold iOS arms exhausted 300 seconds with empty output, while later arms passed; the unchanged replay with a warm simulator ran all eighteen Apple projects. SSH reachability alone was insufficient, and a missing or broken simulator must fail rather than masquerade as a no-Mac skip. Start each VM under `systemd-run --user --scope -p MemorySwapMax=0` so host swapping cannot stall the guest.
