# Measurement

Historical `tsgo` commands below are pre-switch (tsgo); the current frontend is in process.

What a number means: instruments, censuses, counts and the populations they cover. Most wrong conclusions here were correct measurements of the wrong thing.

Each line is a rule and the reason it exists. Add one when something costs you time that a rule would have saved; delete one when it stops being true.

- **Before landing a lowering change, build `runtime/node` with both the old and new binary and diff the refusals, and also measure the corpus that made you want the change; zero movement in every column means that corpus cannot see the change, not that it passed.** A rule typing `object` parameters as `void *` was green on every GTK check yet silently refused 94 runtime/node sites, and a later change came back identical on both bracket corpora and a green gate while costing the React port 1,077 refusals, because the construct it folded is written only in React.
- **Before building for a census row, read two or three real cases from the population to see which syntax they use and which lowering path that takes.** Clearing "an accessor, which is a call" (705 occurrences) for class `get`/`set` made the count fall and every fixture pass, but the test262 files it was for all used the object-literal form, which a different lowering function handles.
- **Before acting on a census row, re-run that row's files against the current binary, and start long censuses after your last commit, not before.** A two-hour test262 census pins the compiler when it starts; its second-largest row (135 files) had already been fixed by a commit made 40 minutes into the run, and the report gave no sign.
- **Treat a type-check error as the "sole root" of a failure as an upper bound only, and re-run the selection with the root removed before predicting its yield.** A program that fails type-checking is never lowered, so it hides every lowering blocker behind it: fixing one root of 483 files cleared just 7, and 475 then stopped at a lowering or backend refusal.
- **After adding or changing a skip, check that the gate's summary count moves, not only that the red went away.** The gate's interop step counted an example as skipped only if its output said `SKIP`, so Apple fixtures printing "not run -- no Mac reachable" were counted as ran, and a green gate reported 49 run while 11 did nothing.
- **After adding or trusting a differential spec, measure which of the module's functions the corpus actually calls (`corpus-reach.mjs`), and control the spec against a deliberately wrong implementation.** "116,725 comparisons, 0 divergences" for `buffer` came from calling 4 of its 18 functions, and the whole corpus reached 147 of node's 571; one spec compared its input against itself because `util.styleText` prints nothing without a TTY.
- **To tell a hollow differential spec from a real one, mutate the module (replace every member with `undefined`) and check the answer changes; counting distinct answers cannot tell them apart.** 39 of 273 specs return one value for every input, which looks the same whether the spec reads nothing or is a genuine verdict like `deepStrictEqual(a, a)`; a typo spec reported 574 comparisons and 0 divergences because both sides threw the same error.
- **Validate every benchmark run with an arm that reproduces a number already recorded, placed at both ends (base, variant, base), rather than by checking that the machine looked idle.** An idle check by process name missed `rustc`, `cargo` and `node` in one night, while the reproduce-a-known-number arm caught two contaminations; a variant reported as "5-8% worse" turned out to sit inside the base's own 3.7% spread once the base was run on both sides.
- **For any change that adds copies of functions, report refusal sites and emitted definitions per module beside the occurrence count, and judge it by those two.** Each copy re-reports every refusal inside it, so a change that cleared 19 sites raised occurrences by about 130, and copies built for everything then left for dead-code removal added 273 refusals with identical definitions (a copy that inherits `exported` is also never removed).
- **Beside any corpus total, print how many modules contributed at least one line, and compare per-module counts rather than only the sum.** A `runtime/node` census run while `/tmp` was over quota read 24,030 refusals instead of 25,738, because a module whose output write fails prints nothing and no error, so the missing module looked like progress.
- **Before trusting a number, say which decision it settles and check it measures the quantity that decision reads; print the whole row behind any ratio; and when an estimate is a sum, check each term against its own artifact.** A correct "a try/catch costs zero instructions until it throws" was irrelevant because the inliner budgets total method size and the clock does not track instructions; the same night a three-term estimate built from stand-in numbers landed exactly on a threshold by three errors cancelling, and a "1.00x against node" turned out to be the fastest of seven columns at a hardware ceiling.
- **When a plan rests on a measurement rather than a failure, write down the question the measurement did not ask (which object, which layer, which direction) and build a baseline arm before trusting it.** Two true, relevant notes about how node pauses and resumes a child's stream would have broken `pipe-dataflow` again, because in our runtime `resume()` reaches a different object than the parked host socket, and re-measuring only confirmed the correct numbers.
- **When a fix adds a lookup to an append, insert or update path that runs per element, time it with a few thousand elements at two sizes against the old code.** A move check in react-gtk's child protocols searched the list on every append, green on every driver since they mount a handful of children, and a 20,000-row bench showed an O(N²) term; fixing it and a similar older one took 40,000 labels from 520 ms to 372 ms.
- **State a count's unit in words before using it, print one matching line before trusting a `grep -c` (a wrong pattern also prints 0), join tables on a key rather than by position, never summarise a stream with `head` or `tail`, and diff refusal texts rather than counts.** "Six sites" was six wrapped lines, four instances and three distinct kinds; `^func` matched nothing because the real prefix was `export func`; one missing field shifted every later row and showed eleven modules changed when one had; and equal refusal counts hid six new refusals replacing eight vanished ones.
- **Before landing a change to which code is emitted, name the quantity each instrument measures, drive every grammatical form of the affected construct against node, and treat the gate's agreement checks as the measurement.** A change landed on +169 definitions and fewer refusals replaced a refusal with a silent wrong answer for `try { } finally { }` without `catch`; three refusal censuses that all agreed measured only "what does not compile", while the wrong fold was caught by one example disagreeing with node on 28 cases.
- **Run a new command once unfiltered, take its exit status from an unpiped run, check the artifact exists, and write filters to answer the question rather than to shorten output.** `nts emit-c -o dir` (the flag is `--out`) printed one usage error and wrote nothing, which `grep NTS` read as "nothing refused"; in the same family `cmd | tail; echo $?` gives tail's status, and a `| head -6` turned 1,242 layouts into "only 6", inverting a conclusion.
- **Before reading a function count, say which roots produced it and which roots the product ships with (for an app, `hir --prepared --main`).** Bare `nts hir --prepared` roots at every export and ignores `nts.config.ts`, which over-counted React's GTK and Adwaita apps by 18-32%, and led one lane to read "637 lowered and then pruned" when the real number was 2.
- **Report every yield measurement for a compiler change together with the gate's recorded test262 and outcomes steps run on the new binary, excluding negative tests.** A rerun over the 4,879 files the change targeted showed 165 fixed and 0 worse, while the recorded check on the same binary showed 243 previously passing files regressing outside that selection.
- **Never re-record a stale gate table just to make it green; raise only the rows you can account for, and set any "earned a lower bound" hint wider than the headroom.** The `definitions` table had drifted 7,211 functions behind (so zlib could lose 359 functions and still pass) and the test262 floors 72 passes behind, because both are re-recorded only as a side effect of unrelated full runs and their constant warnings were read as noise.
- **When checking a fixture with `nts check`, read the last two lines and compare the function count against the exports minus listed refusals; never read `tail -1` alone.** A change that made 3 of 12 functions refuse still printed "agreed on every case" on all five arms, because `nts check` exits 0 and compares only what still compiled, and the count line saying 9 functions sat just above the verdict.
- **When writing a stand-in for someone else's test harness, transcribe its comparison from the original source rather than reasoning it out.** The census harness used `!==` where test262 uses SameValue, so every NaN assertion failed and every ±0 assertion passed whatever the compiler answered, hiding three real `-0` defects as passes.
- **Decide whether a build emitted a function from the artifact itself (bytecode via `javap`, or the emitted C), not from which names its messages mention.** A per-module diff of declined functions took names from the backend's `(in fn)` suffix, but lowering refusals print only a path and line, so a function main had refused at lowering was reported as one main emitted and the candidate now declined.
- **Before saying "zero across N" or "nothing else moved", write down what N is a sample of, ask which set contains the thing you changed, and run the real gate (`pinned.sh <sha>`) before trusting a hand-picked subset.** "Zero emitter diagnostics across every example" never included `runtime/node` (built by a different script), so making them fatal regressed 16 of 24 modules; a `Math` change was cited against test262 `language` when `Math` lives in `built-ins`; and a census of 646 of 1,248 configs missed all of React.
- **When a number looks good, ask what could not have contributed to it, and before committing an example compare its export count with `nts check`'s "across N function(s)".** Every instrument here counts events, so a missing export, an example that never runs or a refused function is invisible and reads as fine: a new example "agreed on every case" while three of its seven exports, the ones written for the feature, had been refused and silently dropped.
- **Before counting a lane's passes, check what each module actually publishes on that lane, run an "empty the module" arm on every module, and treat a test that passes on one lane and fails on the other as suspect on the passing side.** A compiled-lane total reported as 75 was 50, because `cluster`'s addon published nothing and 25 tests branching on `isWorker`/`isPrimary` took neither branch and passed; other hollow passes compared two absent values for identity.
- **Before implementing a node module, run `tooling/conformance/module-yield.mjs` instead of trusting the count of test files whose name starts with the module.** The name-prefix count said `tty` had 3 tests and `dns` 30; the real addressable yields were 0 and 1, because tests carry the name without requiring the module, need c-ares, or substitute internals.
- **For each artifact a command can emit, ask which gate step consumes it, and where none does add at least a cheap parse check.** `nts emit-llvm` produced IR that `llvm-as` rejects for two runtime modules and nothing noticed, because the gate's LLVM step only builds the examples; `llvm-as <f> -o /dev/null` costs about a second per module.
- **When a check reports a surface as complete, ask what it enumerated (module keys or prototypes too, examples or benchmark cases), and add a floor that fails if the probe stops reaching what it should.** A readline test titled "surface, complete" compared only module keys and missed 21 prototype methods for months, and the JVM gate step reported 205 of 205 examples while eight benchmark classes emitted nothing loadable.
- **Budget the first run of any new instrument for finding the instrument's own bugs: read one full result before the count, sabotage the subject to see how many inputs notice, and test failure paths with a positive control.** Two new differential corpora reported 423 and 6 divergences that were a wrong output sink and a shared registry key, a clean stream corpus caught a deliberate bug on only 1 of 30 inputs, and a `cc-failed` verdict that hid its error text turned a full `/tmp` into a reported compiler bug.
- **When an excluded feature reports passing cases, first ask whether the feature can exist at run time, and if not, look for assertions a static fold could answer and probe with a side effect in the operand.** Nine `Temporal` tests "passed" with no Temporal runtime because nts folds `typeof f()` from the static type without calling `f`, and those hollow passes inflated the floor.
- **Profile the binary whose behaviour you are explaining, and before reading any A/B result, name what the two arms differ by; if it is more than the change, rebuild the baseline.** A profile showing 96% in tsgo's garbage collector came from the old binary and sent hours of work to the frontend, while the new binary was 100% nts with 41% in one analysis cloning a map; a saved census from earlier the same night attributed three intervening commits' effect to a one-call fix.
- **When a census run is flagged DEGRADED MACHINE, run it again and compare the two row by row (`rows.mjs --diff`); record it only if nothing moved, and say so in the commit.** The swap-traffic threshold stands for "load moved an outcome", which can be checked directly: two full runs at 502 and 2,458 pages/s agreed on all 30,179 rows, instead of waiting all night for a quiet box.
- **When a change clears refusals, treat the extra compiled functions as a symptom to check, and run `cargo test`, not only the corpus instruments.** A narrowing change measured as 22 fewer refusals and 146 more definitions with every differential agreeing, yet it let an object be read as a wider type whose slot it does not have, and only a control assertion inside a unit test caught it.
- **When `cargo test` and a release `nts` disagree on one input, suspect the build profile before staleness.** A pointer comparison (`std::ptr::eq`) on a `const &str` depended on whether the linker merged copies of the constant, so one example compiled to 17 functions and 0 refusals in release but 8 functions and 3 refusals under `cargo test`, and every instrument (all release builds) was blind to it.
- **When renaming or migrating files, grep every selector that could name them (owed.mjs rules, all.sh steps, audit globs) and give each selector a self-test that names one real instance of its subject.** After tooling moved from `.mjs` to `.ts`, owed.mjs's "an instrument" rule still matched only `*.{mjs,sh}`, so for a day no tool change owed a self-test, and the empty checklist read as "nothing owed".
- **Run a tool's cheap self-test arms on every invocation and refuse the whole run (exit 2) when one fails, instead of hiding them behind a `--self-test` flag.** The gate calls tools with no flags, so seven must-fire arms added to jvm-verifies.ts behind `--self-test` guarded nothing where it mattered.
- **Look a refused function up by name in `nts refusals <module-dir>` before bisecting, and check that every bisect arm still typechecks before reading its zero.** Six worktree arms "proved" a wrong cause for a perf_hooks refusal because each had deleted an import's only use, failed to typecheck and so printed no refusals, while `nts refusals` named the real cause (`weakResource` of type `WeakRef | null`) in one line.
- **For every artefact or diagnostic stream a command can emit, find the gate step that reads it, and where none does, add a parse or a load.** Nothing in the gate consumed `emit-llvm` or `emit-jvm` output over the runtime: the first parse found 24 of 27 modules' LLVM invalid and the first load found 18 of 28 failing the JVM verifier.
- **Assert that an artifact exists, as its own check with its own message, before measuring it, and match `file.c:12:3: error:` rather than a bare `error:`.** `clang … | grep -c "error:"` returned 2 against a directory the emitter never wrote (the lines were "no such file" and "no input files"), and `unzip -l` on a missing jar made a test blame the jar's contents.
- **Never compare a before and an after taken in two different trees; build the old compiler in its own worktree and run both arms in your tree.** A claimed "25 of 26 addons now load" came from a four-day-old `child_process.node` left in `target/node`, because `build-floor.sh` only rebuilds the modules in its FLOOR list, and the same output said only 24 of 24 had built.
- **Use a worktree whose `third_party/node` is a symlink for compile-side comparisons only, never as a baseline for running tests.** `require` resolved test helpers into the main tree, the harness's path-keyed substitution missed them, and 36 async_hooks tests "fixed" by a change were really running node's own async_hooks.
- **Never predict what a fix will publish; remove the candidate cause in a worktree, re-emit, and diff the set of declined exports.** The compiler reports only the first refused callee, so a ranking by count measures how far forward a diagnostic sits: fixing the second-largest chokepoint (`parseFileMode`, ten fs exports behind it) published nothing, because all nine dependents had another blocker waiting.
- **Test every mode a tool has, run it from a worktree as well as from the shared checkout, and make its output name the tree it measured.** owed.mjs's `--commit` replay was right, but its default mode located the repo from the script's own path, so from a lane's worktree it confidently reported on the shared checkout's files instead.
- **For a series of commits, ask `owed.mjs --range main..HEAD` after rebasing onto main, never `--commit HEAD`, and when its answer names no `NTS_INTEROP_PROJECTS` and the range touches a platform lane's paths (`not_run` in lanes.json), bring that platform's VM up before queueing.** `--commit HEAD` judges the last commit alone: a binder series ending in a gtk-gir witness answered "interop gtk-gir", but the range touched `bind_winmd/`, so the train ran every interop project, the Windows ones printed `SKIP` with no VM up, and land.ts refused it after a green gate -- splitting a train of two (2026-10-20). Over a stale base a two-dot range also counts main's newer files, hence the rebase first.
- **Trust a patched pin only when its binary hash equals the pin of the commit it later landed as; otherwise rebuild it before quoting its numbers.** Concurrent pin.ts runs shared one build tree without a lock, so one pin recorded the right patch but shipped a binary built without it, caught only because a result was impossible.
- **For an intermittent hang, add an env-gated watchdog thread to the host that prints its internal counters after a delay, and count any fix over dozens of runs per backend.** A macOS run-loop test hung about 1 run in 20; fixing the first real cause still left 7 of 80 hanging, and only the counters (`readables=0`) showed the second cause, a file-descriptor callback that never fired.
- **Pass `--decompose --calls` when measuring `nts frontend`, and give any probe whose reproducibility matters its own `NTS_SNAPSHOT_CACHE` directory.** The bare command builds a snapshot without decomposition or call resolution that no compilation uses, and before a fix it shared the build's cache key and silently shrank `tests/programs/math`'s program.c from 4,656 to 1,999 bytes.
- **Before calling a category closed or predicting where a family of failures lives, count it in the largest corpus there is (the full test262 census).** "Invalid HIR" was declared done because both known members were pinned, and the full census then held 266 such files including two unpinned shapes; a family predicted to appear "constantly" appeared in 7 files.
- **Ask of every file, config and helper "does anything read or build this?", and answer by comparing it with its siblings rather than by reading it alone.** One awk over three sibling interop `build.sh` files counted `emit-jvm` calls as 1, 1 and 0: the third project's main.ts, holding every construct its matrix column claimed, was compiled by nothing, and a checked-in `bind.overrides.json` cited five times in the design doc was read by nothing.
- **Make every instrument print how many cases it could not run (unparsed, absent, failed to build, crashed, declined), and judge `nts check` by its `checked N of M` and "declined" lines, not by its last line.** A harness reported "agreed on every case" over 16 of 145 cases while 17 were declined because the program aborted, and `blockers-check` reported 29 fixtures needing a person when 28 of them were a full /tmp.
- **Before writing more specs to raise coverage, check that the harness can express the calls you are missing.** The differential reached 9 of fs's 169 functions because the harness contained no `await`, so every callback-taking function was out of reach; making it async took fs to 26 and found two real defects at once.
- **Before giving a verdict on a peer's commit, build that commit's pin and measure the cases the verdict rests on yourself.** An evidence file named a draft commit, but its `after` arm had been built from a different tree, and a regression reported from it vanished when the commit's own pin was measured.
- **Start from the thing you want to publish and walk its refusal cascade link by link (`nts hir --prepared` or `emit-c --napi`), rather than working down a census ranking.** Walking `http.createServer`'s cascade found eight different root constructs in a day, none of them ranked by any census, and two links pointed at a refusal that was never printed at all.
- **Before acting on a cascade line, grep the named callee's source for the construct the sentence blames.** A table keyed class members by bare name, so a method and a module function both called `names` shared one entry, the function was blamed for the method's regular expression, and a night went into excluding a cause that was never there.
- **Make a census record each run's exit status and count `invalid HIR` lines beside the NTS codes.** `emit-c` on React's native probe printed invalid-HIR errors, which carry no NTS code, and exited 1, so `grep -c 'NTS[0-9]'` gave 0 and read as the best census yet while nothing had been emitted.
- **Treat every line of lint or gate output as yours until its path says otherwise, and grep gate logs for imperatives such as "raise the floor", not just for the verdict.** Four `unwrap_used` warnings seen two commands earlier failed the gate, and green runs asked all night to raise a floor from 210 to 238 without anyone reading it, leaving a ratchet that could not catch a regression.
- **Quote each check's own output and exit status in whatever you write, and read the emitted artefact (C, bytecode, HIR) before writing a mechanism into a fixture, commit or doc.** A gate was reported green while it was still running and came back FAILED, a fixture header explained a cause the emitted C contradicted, and a "before" number in docs/wasm.md had never been measured.
- **When a change you are about to land depends on a defect that another pending change removes, land the fix first and re-measure.** One patch measured an extra vtable word in ten modules on one base and exactly zero once the blind spot it leaned on was fixed, so every number for its commit message would have been false one commit later.
- **Copy any binary or output directory before a long measurement reads it, and state which tree and commit every number comes from.** A sweep read `target/node` while another session rebuilt it (buffer "0 passed", then "1 passed" on the same build), and a count published as 350 had been taken in a worktree while main held 339.
- **Compile runtime/node modules through `runtime/node/build.sh` (or add its two `-include` flags) before quoting a clang error count.** A bare `clang -fsyntax-only` on `emit-c --napi` output reported 20 errors for `process`, plus 21 implicit `nts_uv_*` declarations that vanish when the module is built the way it really is.
- **Pair every census of diagnostics with a census of silent declines, and check program.c for a missing symbol before hunting for a diagnostic.** A generic function that reads its rest parameter was dropped with no diagnostic at all, and 41 of `timers`' 57 failing test files stopped at one of the three functions declared that way.
- **Normalise synthetic ids (`<N>`, `objN`, `ClosureN`) out of refusal messages before diffing them, and measure both source states with one binary.** An edit renumbered the ids, so a raw diff showed 564 changed lines, which normalising reduced to the 6 that were the real change.
- **Use `nts hir --prepared` (or `emit-c --napi`) to ask whether a function reaches a backend; plain `nts hir` shows raw lowering without the cascade.** A constructor printed as `export func` by plain `nts hir` was absent from every backend (http has 892 cascade refusals that the plain dump omits), and a root was wrongly reported as cleared.
- **Never rank compiler blockers by counting diagnostic message texts; reduce each one to a minimal program with two controls first.** One cause prints several messages (a `RegExp` value is refused five different ways depending on where it is written) and one message covers several causes (42 "method with no declaration" sites split into at least three), and even the file list in a tsconfig changes which message the same source gets.
- **When a diagnostic names a declaration rather than an operation, replace the suspect expression with a trivially supported one and rebuild.** A `Buffer.from` call showed up as "a declaration outside every walk" in `os` and as "calls Buffer.from" in `string_decoder`; an hour of reading the message lost to one substitution that cleared every refusal in the file.
- **Rank work by the failing test files a cause blocks (the groups `next-pass.mjs` prints), tracing each large group to the constructor or declaration that stops it.** `options = {}` in `net`'s Server constructor sat eighteenth by diagnostic count yet blocked 332 node test files, five times the next item, and in seven of the nine largest groups the message described something other than the cause.
- **Rank a blocker by what becomes true when it clears (the cases whose only root it is, minus boundaries already declared permanent), not by how many modules or files reach it.** Three real compiler fixes moved the refusal count and not one compiled module, a 147-file "missing builtin" row was 140 files of `eval` (a non-goal), and a plan item justified by 1,417 files was the sole blocker of 8.
- **Before a known-failures list is used to rank work, classify its entries from the programs' raw names, not from their shared normalised reason.** 75 `integrity.known` entries sharing one reason were five different defects, and one of them was a one-line fix that had been hiding the real cause in fifteen `fs` cascades.
- **When an instrument reports a bucket of skipped or declined cases, ask which distinct causes land in it and whether the skip rule is right for each.** The differential merged "an index out of range" with "an uncaught throw" into one declined state and dropped node's answer for both, so an example with 17 of 174 cases aborting printed "agreed on every case".
- **Before summing or comparing counts, check that the groups do not overlap and that both sides of the comparison used the same key and the same file glob.** Eight conformance files were claimed by two modules (two passing in one and failing in the other), a `find` over `runtime/node` counted 441 generated `.d.ts` re-declarations, and occurrence counts overstated distinct sites about 10x because one generic in a widely imported file was reported 294 times.
- **Under a harness that substitutes a single module, do not trust an `instanceof` that crosses a module boundary; use a realm-independent check or mark the behaviour as not comparable.** `run-one.mjs` compared our `Buffer` class against node's, called correct buffers "not a Buffer", and reported 524 divergences that were the harness, twice.
- **Time each code shape in its own process, selected by argv, and write the probe that way from its first line.** A probe timing two closure shapes in one JVM made the shared call site megamorphic and reported a trampoline as three times faster than the code it wraps; one process per shape showed them identical.
- **When derived views of a data structure disagree, or each one clears your suspect, dump the structure itself, keyed by the identity the bug is about.** Hours of inference from emitted C, `nts hir`, a substitution map and type records could not explain why four generic instantiations shared a layout; ten lines printing each layout's type list showed one layout had absorbed three others' ids.
- **On a failing test, extract `file:LINE` from the stack and read the surrounding lines before forming a hypothesis, and treat the line as approximate until a direct check agrees.** Four probes of `path.resolve` all agreed with node because the failing line was patching `process.cwd`, not exercising `resolve`; a second test's reported line was two lines off through the harness's `eval`.
- **After any change that can produce invalid HIR, check for it directly (emit every runtime module and grep "invalid HIR", or read `emitted-diff`'s count of measured projects), because the census and `refusal-diff` cannot see it.** One change left six runtime modules emitting nothing while `refusal-diff` reported "0 moves to a loss" and `emitted-diff`'s last line said "23 of 23 byte-identical" over a population that had shrunk from 29; another measured clean on census and agree and then failed four gate steps.
- **Never set an environment variable that changes program output (`NODE_NO_WARNINGS`, `FORCE_COLOR`, `NODE_OPTIONS`, `NO_COLOR`) on a conformance or differential run, and suspect the environment first when a comparison disagrees only on formatting.** `NODE_NO_WARNINGS` hid the warnings two node tests assert on and led to a bisect and a wrong ledger correction, and an inherited `FORCE_COLOR=3` made node print colour codes and turned three gate steps red.
- **When a row regresses, re-run the previous build's kept artifact against today's tree to separate compiler causes from environment causes, and load each artifact once before trusting its row.** Two modules each lost a file overnight: the old artifact still failed for one (a harness commit had deleted its pseudo-terminal path) and still passed for the other (a real compiler regression), and a `.so` with one undefined symbol read as 92 failures.
- **Run any type-checker hook on a large real program with its library present, time it, check the exit status, and diff its diagnostics against the unpatched checker.** A hook that passed 48 baselines and 11.8M oracle checks ran 21x slower, overflowed the stack and crashed on an intersection type when pointed at TypeScript's own compiler sources, and the one run that looked fast was the crash.
- **Before writing a benchmark row to measure a change, compile its shape on every lane the gate runs, and if one lane refuses it, record which lanes the before number covers instead of reshaping the row.** A row meant to price interface indirection could not exist on the JVM, which refuses a class stored in an interface-typed slot, and that showed the planned change was pure gain there.
- **After a change to scoping or representation, diff the full test262 census per file against the previous run, and look for an example named after a behaviour before claiming nothing covers it.** The gate only checks floors and expected failures, so a green-gated change silently made four previously passing test262 files refuse (a loop's `var` read after the loop).
- **Measure a timing defect by moving the event rather than adding output near it, and make a generated artifact state its own counts instead of having readers grep it.** A `console.error` added to debug a cluster handoff race made the failing test pass every time, and a comment telling readers which token to count added that token and moved the count from 2 to 3.
- **After editing `runtime/node` TypeScript, build the module with `tooling/conformance/build.sh` instead of trusting the interpreted lane.** `run.mjs` imports the `.ts` without typechecking, so it read 406 passed / 0 failed while an unused import made `emit-c` refuse the module and turned the shared gate red for an hour.
- **For a benchmark that reimplements a host builtin (JSON, URL, TextDecoder), measure against the builtin separately and say which comparison each number is.** The bench's node column runs our TypeScript on node, so JSON rows at 0.98-1.26x hid that our parser was about 4x slower than node's native one.
- **For a compiler change that widens what compiles, run the recorded test262 sets and both `integrity` variants on a pin before landing.** Two commits passed 1,348 unit tests, clippy, `emitted-diff`, `refusal-diff` and `blockers`, then turned main red: 112 test262 files regressed on a construct (a class private generator method) that `runtime/` never writes.
- **To learn why a program has some property, read the emitted artifact (`javap -c -p`, or `nts hir --prepared` with the real `--entry`), not the pass's source or a printed model.** Four conclusions in one night were wrong this way, including a dispatch slowdown blamed on inlining in a program whose class file contained no virtual calls at all.
- **Read a check's whole output, never just its tail, and when the program under test gains a new way to write to the channel the instrument reads, re-check how the instrument counts.** Once programs could `console.log`, the differential counted log lines as answered cases and turned main red with a phantom decline, while `tail -2` still said "agreed on every case".
- **Measure a performance claim used to justify not doing something, just as you would one used to justify doing it.** A ledger entry said routing the cwd through JS would slow `path.resolve`, but node's cached `process.cwd()` costs 11 ns against a `getcwd` syscall every time, and `resolve` was 5.4x slower than node for an unrelated reason.
- **Before adopting a soundness guard or test built on a whole-program flow fact, run `emitted-diff` over the runtime modules and read the helper-call counts; a fixture corpus cannot see how conservative the fact is.** A guard testing every owner the flow said could reach an interface through `unknown` passed all 167 outcome fixtures and grew `zlib` by 4.5 MB (`nts_is_class` 1,349 to 69,058, `nts_refused` 6 to 1,012), because in the runtime almost every class reaches almost every face.
- **Check a pattern that reads a tool's log against a real log of that tool, not against the line the tool's author quoted.** The land-time rule for a skipped Windows or Apple run was written as `^\s*SKIP`, which matched nothing: the interop step reprints each line as `<project> skipped: SKIP ...`, so the rule would never have fired.
- **When a change's timing is surprising or the machine is loaded, count before you time: a fixed-iteration driver printing `nts_counted_allocations`, `nts_cycle_candidates` and `nts_collection_epoch` per run gives load-free numbers that attribute the change.** A one-unit string table that removed 4,000 allocations a parse timed 13% slower; the counts showed the parser change beneath it had raised cycle candidates from 4,002 to 14,009 and added a collection per parse, which no timing could have separated from load.
- **Hold admission between cases under memory pressure, never SIGSTOP timed work, and prove that an active case finishes while the next waits.** On 2026-10-18, process-group pauses cost CompilerHelper two complete test262 language records through false timeout regressions; one pause lasted 318 seconds across a 120-second emit timeout. The feeder-only control then held admission for 5 seconds across a 4-second case timeout: the active case finished in about 1.5 seconds, and no next case started before resume. A wall-clock timer keeps advancing while its worker is suspended; stopping new conformance cases or gate-pool tokens lets active work finish without changing its verdict.
