# Soundness

Historical `tsgo` commands below are pre-switch (tsgo); the current frontend is in process.

Reasoning about whether the compiler is right: derivations, preconditions, guards, trust and refusals.

Each line is a rule and the reason it exists. Add one when something costs you time that a rule would have saved; delete one when it stops being true.

- **Before a lowering rule re-types a binding, write test arms for a closure-captured-and-written name, a module-scope `const`, and a generic class with two live instantiations.** In `hir/lower.rs` a captured-and-written name is bound to its cell (re-typing it crashed with signal 11), a module `const` is a global with no binding entry, and a generic class has one instance type per instantiation; all three passed a purpose-built fixture, four probes and 360 examples, and only a deliberate wrong-answer arm and the corpus census caught them.
- **When a lookup returns nothing because a value has no machine type, ask whether the caller wanted the machine type or only the binding.** `generics::unify` dropped any type binding that landed on a type parameter (which has no representation), so 46 call sites were refused as "a generic function no call pins down" when the call had pinned it exactly; the real fix was one copy of the callee per instantiation of the enclosing generic.
- **Give a recursive walk one entry point, make anything it consults non-recursive, bound termination with a visited set, and test it on a fixture with a cycle.** A call-graph walk with a depth counter overflowed the stack at 38,760 frames because a classifier it consulted re-entered the walk with depth reset to 0; every probe was acyclic, while real code (`commitRoot` and `flushPendingEffects`) calls itself in a cycle.
- **When one cache decides whether another is consulted, make the outer key cover everything the inner key covers, and test it by changing an input between two builds of the same project.** The GIR binder's cache identity was the constant `"gir-bindings/1"`, so after a GIR file changed the snapshot cache hit, the generator never ran, and the program compiled silently against stale bindings.
- **Give every patch carried in `third_party/patches` a test asserting its invariant against the pinned source and a freshness rule that rebuilds tsgo when the patch changes, plus a test that actually runs the frontend.** Nothing goes red when a carried patch disappears: Go still builds and only an answer deep in lowering changes; without the first patch (which reports each type's `ObjectFlags`), 243 test262 passes were lost.
- **When a verifier rejects a program that looks correct, first check that the verifier and the pass that would fix it walk the same collection.** The verifier walked `Func::values` while the repair pass walked `block.ops`, so a store that dead-code elimination had removed from the ops was checked but never fixed, and seven test262 files were silently unbuilt.
- **Before relaxing a run-time check, find what downstream code assumes because of it, and exempt only what is known at compile time.** Dropping the presence check on assertions (on the principle that `as` keeps TypeScript's erased meaning) turned five gate steps red with a signal 11, because after `value!` on a null the compiler trusted the type, folded `=== null` to false and read `.length` through null.
- **Treat a comment that says what node (or our own code) does as an unchecked claim: when writing one, quote the upstream line with its path, and when relying on one, print the artifact it describes first.** A comment saying "node does not end it either" sat beside code that left `process.stdin` from `/dev/null` open forever while node's vendored source ends it immediately, and a napi comment naming a cause and a fix was refuted by one `nts layouts` command, saving a four-backend change for zero gain.
- **When a guard is stated over a population ("every function", "every symbol"), list what the language has outside that population, and for any name-keyed resolver check constructs named by a keyword (`constructor`, `super`, `static {}`, `get`/`set`).** A `static { }` block lowered to nothing, producing zero refusals and seven wrong answers, because the "every function is lowered or refused" law counts symbols and a static block declares none; later a resolver keyed on an identifier returned a constructor's signature instead of its body.
- **When a silent wrong answer could be closed by refusing, first read the chain that decides whether the case could work, and before adding a refusal ask which body it will be emitted into.** Three successive fixes each turned a lost `throw` into a correct refusal at real cost elsewhere, while the real fix was one too-narrow arm four functions away whose own doc stated the general rule; and a refusal inside a raising closure variant becomes a run-time abort, which turned a passing test262 case into a crash.
- **When a symbol lookup on a declaration node answers nothing, do not read it as "no symbol": find the symbol whose declarations list contains the node instead.** In nts's encoding a function declaration or parameter carries no symbol (its name child does), and two lookups failed quietly as an empty set and a false predicate, letting a `throw` escape.
- **When a note argues "if X, then Y would break", write the three-line program that checks whether Y is already broken before filing it.** A correct argument against a fix said that differing interface and class field orders would read wrong offsets silently, and it was already true with no change: a class declaring `id` before `name` crashed with SIGSEGV where node answered 6.
- **Before deleting a declaration or pass, ask which other crates consume what it wrote, and prefer publishing the fact explicitly over leaving consumers to re-derive it.** A deletion checked as unreachable within `hir/` silently removed the JVM backend's whole Java-callable surface for six weeks, publishing an API Java could not call, and the failing check's suggested fix (`NTS_REGENERATE=1`) would have recorded the broken API as the new baseline.
- **When a doc sentence says "anything", "every" or "never", read the code that implements it and ask what else is in that universe.** A length-folding rule documented as "an array handed to anything loses the claim" checked only call arguments, so a closure capturing the array let `.length` fold to 0 where node answers 1.
- **When you clear a refusal or implement a missing feature, grep the docs for the gap's own words, and when a comment names a future improvement, write the two programs on either side of it to see whether it already exists.** Prose saying something does not work tells readers not to try, so it is never refuted: one day found three such stale claims, and a 74-site refusal's comment proposed a refinement that had already been built.
- **When a constructor does work, pass everything that work consults as a parameter, never as a field patched on the next line.** The Objective-C binder's model spelled every member while `platform` still held its "macOS" default, so every iOS binding checked availability in the wrong domain for months, refusing 20 UIKit members instead of 524 and offering API that would crash on device; macOS tests passed because the default happened to be right there.
- **For every refusal or guard, ask which call sites actually reach it and write the answer beside it; before turning a gap between two tables into work, write one program that reaches each item.** A JVM refusal with a precise message was read as proof a design was safe though nothing called it; of twelve refusals in one lane only eight could fire, and six of eight "missing" runtime helpers could never be emitted on that backend.
- **When a rule concludes from what a body does not contain ("no `super()`", "no `return`"), first filter to declarations that have a body, and add the `interop` gate step for any lowering change touching classes, constructors or calls.** A rule that a derived constructor calling `super()` nowhere never binds `this` fired on bodiless native `.d.ts` constructors, so every Objective-C subclass construction counted as throwing and an interop example lost three functions while its build exited 0.
- **Key diagnostic tables by the emitted or fully qualified name, and when a diagnostic names a cause but has no source line of its own, check which key it was found under and grep the callee for the blamed construct.** A refusal table keyed by bare member name let one function's reason ("a super keyword is not supported") be printed for another's failure, which cost a night building a `super` lowering for a site where `super` was never the cause.
- **When a predicate turns on a collection being empty, find every way it can be empty before choosing what empty means, and if one is "an input was dropped", fix the drop upstream.** An empty declarations list meant both "does not throw" and "the frontend dropped the handle"; treating empty as "may raise" cost 379 refusals and 485 definitions, while fixing the drop cost 88 refusals at unchanged definitions and cleared 39 unrelated ones.
- **Before an analysis trusts a declared fact, list every entry that bypasses the obligation that justifies it (exported roots, callbacks from C, addon wrappers, vtable slots, JVM callers) and make each one enforce it.** Trusting `n: c_int` because every in-program caller proved its argument fits made exported functions' `(int32_t)v` undefined behaviour when a C host or JavaScript passed `3e10`; a check placed inside the trusting body is folded away by the trust itself.
- **Before exempting members of a set, grep every `insert`/`extend` into it and check the argument holds for each producer.** An exemption argued from skipped reassignments (which leave the earlier value) also covered cut initializers (which leave zero) feeding the same set, so `const label = made.label` with `make` refused crashed every module load for a day.
- **When a failure is labelled someone else's problem, ask what our side does when it arrives: did the other process die, or did it just return an error we made fatal?** Seven censuses recorded 18 "tsgo panic, not a gap of ours" files without investigating, but tsgo recovers every panic and returns an error; only one of our request paths degraded gracefully, and a 40-line fix gave the rest the same path.
- **When you add a property to a whole class of objects (a base, a field, a modifier), or touch a feature a refusal mentions, grep the tree for the invariant's own words to find code and comments that rely on its absence.** Giving every generator frame a base falsified a correct doc comment three crates away and the JVM backend threw `NoSuchFieldError`; a `try` around a foreign call compiled with no exception table because "only compiled code can throw" stopped being true when a new backend arrived, and a refusal of object-literal methods outlived its reason for weeks.
- **When one fact is derived in two places, make one call the other or delete one, and if both must stay, assert them equal or abort loudly when they part.** Four defects in one session were each a general derivation that stayed right and a narrow one that rotted when its blind case became reachable (field ownership by index arithmetic, number formatting with `%g`, map-key identity by one tag), and a guard and the body it guards disagreeing about one type turned two agreeing async examples into aborts.
- **Before reusing a predicate across an analysis boundary, list every case it answers yes for and ask the narrowest question that names yours; and check a test expectation on the final version of your change before editing it.** Reusing the lowering's `calls_a_closure` also matched calls with no target, such as `value.toFixed(d)` on an erased `any`, which the real lowering cannot dispatch, adding a refusal that a core test had already been "updated" to expect.
- **When a predicate approximates a set the code already enumerates, test membership in that enumeration instead.** "Uppercase and at most 7 characters" stood in for the 14 Swift number names, so optionals of `UILabel`, `UIColor` and `NSURL` silently read as non-null until a fixture read nil from one.
- **When a refactor only reorders a list that later code scans first-wins, treat the order as an input and find who reads it.** Pushing a generator closure's body before its raising copy changed which resume the shared generator class got, and 17 test262 cases regressed with no function changed.
- **When a representation, layout or verify rule changes, re-run the census rows of refusals written because of the old rule instead of trusting their comments.** Nothing goes red when a refusal outlives its cause: deleting one stale refusal and nothing else made 36 of 40 test262 files pass.
- **Read a refusal's predicate beside its message, and give each failing branch its own sentence naming the value that decided it.** One predicate with three early returns printed a sentence describing only the third, so 55 of the corpus's 77 top-cause sites were really an absent field and a planned fix chased the wrong mechanism for a day.
- **Make a check collect every problem instead of stopping at the first, and when a refusal names one cause, ask whether it is the cause or only the first.** `bind-c` named a function-pointer member as the reason it refused `struct sigaction`, work went into function pointers, and the record still refused because of an anonymous union behind it.
- **When things are merged on purpose to share storage, list everything derived from the merged thing (names, identity, dispatch) and derive those from the unmerged thing instead.** Two object literals of the same shape shared one layout and therefore one method name, so `b.which()` ran `a`'s method and the program printed 11 where node prints 12, with no diagnostic on any backend.
- **When a helper is built on a neighbouring helper, check that the neighbour's edge-case answer is specified to be the same.** `codePointAt` was written in terms of `charCodeAt`, whose NaN for an out-of-range index is correct, so it answered NaN where node answers `undefined`, on every backend.
- **Ask how many places decide (and read) a fact, and test that its owners agree rather than testing each one.** Nine defects in one day were facts with two owners that disagreed; in one, a class member's emitted name was built in three places and only one read the disambiguation map, so two modules exporting `Thing` got no vtable and crashed with exit 139.
- **When a refusal survives several compiler updates unchanged, re-read it as a statement about your own source.** One message persisted across nine compilers and was filed each time as a runtime gap; it was an export typed `isatty(fd: unknown)`, which the Node-API boundary cannot represent, and it took twenty minutes to fix.
- **Keep a refusal only when its output cannot be checked on this machine, not because its inputs are awkward to make; check `command -v <tool>` first.** Android dependency packaging was refused because "no fixture has such a pin", while `d8`, `aapt2` and `jar` were installed and a test could build one in about fifteen lines.
- **When a change clears a refusal, run the broadest sweep (addons.sh for lowering, the interop sweep for emitters) before committing, and read a regression as what stood behind the refusal before reading it as what you broke.** Defaulting Windows targets to the C backend produced an ELF `libsdk.so`, and a correct lowering change took addons from 24/24 to 17/24 by exposing old defects, which once got a correct design reverted for three days.
- **Before writing a text-matching discriminator, look for an invariant the compiler already guarantees and read that instead.** A refusal-diff rule matching a cause's message never fired because many sites write the same text; asking whether any refusal cites the function as a callee, which `verify` guarantees is the only way it can still be wanted, worked first time.
- **Check each candidate cause against the ordering the failing test actually asserts, tracing both sides against node, before recording it.** One cluster test carried four recorded causes over its life, each a real and verified mechanism and none of them the defect, which was a worker leaving `cluster.workers` on exit where node removes it on disconnect.
- **Put a run-time guard where the wrong value would be read or written, not at the cast that makes it possible, and run the definitions census before believing a guard is free.** Testing the class at the cast stopped seven correct web-platform functions that only called methods; moving the test to the field access cost nothing.
- **When a rule looks correct, ask what reaches it, and when a defect shows at only one site, suspect the other sites agree by coincidence.** A correct WeakMap rule was unreachable because the walk used `Object.keys` and skipped symbol keys, and a validator used the parameter's name instead of the name passed to it, visible only in `path.join` where the two differ.
- **At any early return meaning "nothing to do", ask what the construct evaluates, not what it produces.** `typeof f()` never called `f` (21 test262 rows passed by running nothing), a class declared in a block never ran its static block, and `const [[] = init()] = []` was not lowered at all.
- **When a comment justifies a choice by pointing at another backend, read that backend's reasoning, and when you fix one backend at such a boundary, check the others for the same operation.** C, LLVM and the JVM each narrowed a bitwise operand with their own float-to-int conversion, each citing another as precedent, and all three were wrong for 4294967295.0 (`-1 >>> 4` answered 0 on C and 134217727 on the JVM).
- **Before probing a suspected sibling defect, read what consumes the predicate's answer to learn which direction of error is the unsafe one.** Two passes shared the same narrow "does this array escape" test, but the length fold breaks when a closure grows the array and bounds-check removal breaks when it shrinks it; eight probes built by analogy all grew the array and all passed.
- **When a fix causes a regression in a different mechanism, ask what the newly failing lookup used to return before reverting the fix.** Correcting one over-approximate set turned 71 test262 files red because a second over-approximation (an identifier in callee position counted as a function value) had been harmless only thanks to the first.
- **Check a candidate cause against the exact ordering or value the test asserts, and run the probe that could refute a diagnosis before it goes into a commit, fixture header or message.** A hang carried four recorded causes, each a real mechanism verified to exist, and none was the defect (a worker left `cluster.workers` on exit where node removes it on disconnect).
- **Show a new guard firing (print the value it branches on, or dump the record with `nts types` or the IR with `nts hir`) before trusting it, and delete a guard that never fires.** Three guards in one session compiled, passed clippy, both test suites and every behavioural control while doing nothing; one `.ok()` swallowed exactly the refusal it was looking for, and a field named `own` did not mean what its name said.
- **Before adding a reader for builder state documented as "set around X", key that state by X's node id, and test with a nested call of another kind inside the argument.** A field holding "the native call whose arguments are being lowered" was also read by a nested ordinary call, which refused a number and broke the Chromium lane's build within hours.
- **When you split a predicate or remove a wrapper, audit its call sites and also list every behaviour that rode on the old answer (finalizers, collector visits, store, overwrite, container death), giving each a test.** Splitting `NTS_TAG_IS_REFERENCE` with all 24 call sites decided correctly still caused four bugs, because walks written against the old predicate silently stopped releasing handles.
- **Take long constants from the tool that defines them (openssl, a node one-liner, a script over the test vectors) and say in a comment where each came from.** A hand-typed P-521 curve order lost two `f`s, and only three ECDSA/ECDH test files that happened to use that one curve noticed.
- **When you add the first producer of some kind of value (an absent string, a NaN, an empty buffer), check its downstream consumers before debugging your own code, and never attach an attribute that is not unconditionally true.** Adding `String.prototype.at` segfaulted the C test harness and threw NullPointerException in the JVM one because neither had ever been handed an absent string, and a `returns_nonnull` on a function that can return null would have compiled away its callers' null checks.
- **When two places answer one question, find the case neither was written for and ask both, derive the narrow one from the general one, and resist adding a third.** Four bugs in one night (JVM dispatch names, field owners, number formatting, map key comparison) were each a narrow implementation being asked the general question, and in all four the general one was right.
- **Before trusting a "was this compiled" predicate, ask which stage's refusal list it reads: lowering's `program.uncompiled`, the backend's `refused` slice, or HIR itself.** `process` published `env` as `undefined` because a Node-API guard checked only lowering's list while the C backend had refused `module#init`.
- **After narrowing a rule, compare its measurement with the rule it replaced and treat an identical number as a bug, and ask what else reads a list before filtering it.** A "narrow" rule measured exactly the same +1,341 refusals as the blunt one because every function's own declaration name matched it; excluding that took it to +743.
- **For any check that grants permission, ask what it answers on degenerate input (empty, stubbed, unresolvable) and make "not analysed" a distinct answer, and when a change makes generated output smaller, diff it against the unchanged build.** An escape analysis reported 88.5% of `android.jar`'s methods as retaining nothing because the jar is stubs, and filtering native headers silently emptied a header-check while every test passed.
- **When a predicate starts accepting more inputs, first write a running fixture (agreement with node) for what must still be rejected, then probe neighbours such as reassignment, aliasing and shadowing.** Trusting a decided conditional as a direct callee cleared one refusal and added two silent wrong answers, one of which (`let f = yes ? a : b; f = b` still calling `a`) disagreed with node on 27 of 29 cases behind a guard that could never fire.
