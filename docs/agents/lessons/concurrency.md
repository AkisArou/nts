# Working beside other sessions

The shared checkout, peers, processes and gates running at once.

Each line is a rule and the reason it exists. Add one when something costs you time that a rule would have saved; delete one when it stops being true.

- **Run every landing check against a private git index before touching the shared tree, and never loop over `$(git ... --name-only)`; use `-z` with `read -d ''`.** land.sh's `cmp` followed a symlink and refused a correct landing after it had already staged 63 files into the shared index, blocking a peer's fast-forward, and later the same day a path with a space split in a `for` loop, again after staging.
- **Pin everything except the change: run both arms of a comparison from one detached worktree at one revision, and build from current HEAD (passed as `NTS_BIN`) for anything compared against a committed fixture.** An old pinned binary run against regenerated fixtures fabricated a red `interop`, two compilers built twenty commits apart attributed a peer's change to mine, and running the two arms minutes apart while peers landed gave 2,513 false violations that dropped to 6 identical ones in a pinned worktree.
- **Word a gate hold as "nothing in `compiler/` or `runtime/`", have one peer relay it to every lane and release it to each by name, and never land first and gate after.** A hold sent to one peer reached only that peer, so one gated-green commit had to chase main four times as other lanes kept landing compiler commits, each chase costing a 20-minute re-run.
- **Before creating a new module's `tsconfig.json` in the shared tree, measure its refusal count elsewhere and get the gate's ceiling raised first.** Gate steps glob the working tree, not HEAD, so a new `runtime/node/crypto` directory pushed every lane's refusal profile to 16,401 against a 15,500 ceiling the moment it existed, uncommitted, and anyone gating would have read the red as their own.
- **Name the pin and its timestamp beside every compiler number, compare two gate runs only when both name a commit hash, and to check a commit rebuild from it (`pinned.sh <sha>` or `tooling/conformance/pin.mjs`) rather than copying `target/release/nts`.** A copied binary is whatever session last built in its own tree: a defect was reported fixed when the fix existed only in a peer's uncommitted work, a peer's fix was "verified" with a binary built 40 minutes before it landed, and stale pins made freshly landed guard fixtures look REGRESSED.
- **Before starting a gate, check that no other gate is running and announce it, gate the base commit alone first, and stop only your own processes (by working directory), never with `pkill -f pinned.sh`.** A pinned worktree isolates sources but not the machine: two gates at once made clang refuse a probe and made WinUI tests fail on the shared Windows VM, and the lock does not serialise gates because gates do not take it.
- **Run any long sweep from a pinned worktree, and never change the tree, the pinned compiler binary or the running script underneath it.** Four sweeps were discarded in one night for commits landing mid-run, deleting a pin still in use made 13 modules falsely report "did not build", and a temp-file-and-rename edit stripped the executable bit from all.sh for every session.
- **Make every wait on a "running" status file also check that the writing process is alive, and give it a deadline.** A loop waited 45 minutes on `build-result.json` saying "running" after its writer had died (killed by the script's own `timeout 60`), for a build that takes about 80 seconds.
- **Never wait on `pgrep -f` for a pattern you typed; wait on the output file (its last line or its mtime) or on a pid captured at launch.** The waiter's own command line contains the pattern, so `pgrep -f` matches itself forever: four waiters slept for 40 minutes after a gate had exited, and a finished job was twice reported "still running" 84 minutes late.
- **Never put a commit and a message quoting its sha in the same tool-call batch; commit first and copy the sha from the commit's output.** A peer was sent an invented sha three times in one night, each time because the commit and the message went out in one parallel call.
- **Squash onto the branch's own merge-base, gate the sha `git rev-parse` gives now, and check that `git diff --name-only main <commit>` lists only your files before gating or landing.** `git reset --soft main` after main had moved six commits produced a commit that silently reverted all six (27 files instead of 9), and a symlinked `node_modules` committed the same careless way broke `@nts/config` for every lane.
- **Make a multi-step edit to shared code one write where possible, know which modules import the one you are editing, and let a lock check block the action rather than just print a warning.** Other sessions build the working tree continuously, so a briefly unused function in `net` was reported as three modules (`http`, `net`, `process`) regressed.
- **When a step is red only under concurrency, list every fixed path it writes, including source files a test edits in place, and never let a test edit the tree in place.** Four red gate steps came from shared fixed paths (a rebuilt jar, `runtime/jvm/src`, a fixed `/tmp` journal file, `bind-c` probe files), and a concurrent loop reproduced 30 failures in 60 runs of a step that was green alone.
- **Land a change to how gate trees are prepared on its own, before any commit that needs it.** `land` gates with the shared checkout's `tooling/gate/pinned.sh`, which is main's: the corpora move carried its own fix to the workspace links a gate tree gets, and its gate ignored that fix until the fix was on main.
- **Before moving a path, search every tracked file for this machine's absolute checkout path, and never let a generated file that is checked in name an input by one.** The corpora move's gate passed because four checked-in bindings named their C header as `/home/.../nts/examples/...`, which the shared checkout still held while it ran; once main moved, every landing failed `the_workspace_fixture_still_builds`.
- **Never switch the branch of a tree that a running build, test or validation reads.** The command reads sources as it goes, so a switch mid-run tests a mix of two branches; a checked-read validation had to be restarted from the beginning.
