# JVM and Android

TypeScript compiled to class files for the desktop JVM and for Android: what
the backend emits, the runtime beside it, Java called from TypeScript and
TypeScript called from Java, and the jars, APKs and AARs `nts build` makes.
For anyone shipping to a JVM or binding a Java library. The open foundations
(weak references, hashing, `Math`, Java exceptions) are on
[JVM and Wasm](../foundations/jvm-and-wasm.md).

## What is emitted

- **Class files for Java 8** (version 52), with no `invokedynamic`: every JVM
  in use and Android's `d8` accept them, and nothing in them depends on a
  feature Android lacks. `nts emit-jvm --out <dir>` writes them beside
  `nts-runtime.jar`.
- **Classes:** each program has one `Program` class holding its functions as
  statics, in the package the product names (`javaPackage`, `nts.gen` when
  none is given); each TypeScript class is a Java class.
- **Values:** a proved integer is an `int` or a `long`, a `number` a `double`,
  a string a `java.lang.String`; an array is a bare JVM array unless the
  program grows it. A closure implements one of the runtime's callback
  interfaces, chosen by its descriptor, with a single method named `call`.
- **Memory** is the JVM's collector, or ART's (the `HostGc` provider): no count
  is ever inserted, and asking for counting (`--rc`) is declined (NTS2001).
  Weak references are refused (J1 is the proposal).
- **The runtime** is `runtime/jvm` (`nts.rt`), Java 8 sources built
  reproducibly into `nts-runtime.jar`, which carries no `invokedynamic`
  either.

## Products

| product | constructor | artifact |
|---|---|---|
| a library | `library.jvm({ entry, javaPackage, release })` | `<name>.jar`, with `nts-runtime.jar` beside it: shading it in or declaring it is the consumer's choice |
| a program | an `executable` or `application` on `target.jvm()` | a runnable jar: the classes, the runtime and any pinned dependency in one jar, run by `java -jar` |
| an Android library | `library.android({ entry, javaPackage, minSdk })` | an AAR: `classes.jar`, the manifest fragment a package declares, R8 consumer rules, pinned jars in `libs/` |
| an Android app | `app.android({ entry, id, minSdk, compileSdk, arch })` | a signed APK: `aapt2`, `d8`, `zipalign` and `apksigner`, signed with a debug key the build names |

- **A runnable jar's entry is module evaluation.** Its launcher delegates to
  `nts.rt.NtsMain`, which runs the module initializer and then drains timers
  and promise jobs until nothing is left, so callbacks still pending when
  module evaluation returns do run. An uncaught throw exits with status 1, as
  on C.
- An AAR needs no Android SDK: the consumer's build dexes it. An APK does, and
  a missing SDK component is refused by name.
- `release` is the `javac --release` level of a desktop target (8 by default);
  `compileSdk` is the `android.jar` bound against and `minSdk` the manifest's
  floor, two numbers as Gradle keeps them.

## The runtime's event loop

`nts.rt.NtsEnv` is an environment object, not a set of statics: its queues,
timer heap, clock and liveness belong to it, and the current one is a
thread-local. Promises run on the runtime's own queue (`NtsPromise`). The
default environment, the one a runnable jar uses, advances a virtual clock: a
timer fires when nothing else can run, in deadline order, without waiting out
its delay ([async](../language/async.md#the-event-loop-on-each-target)). A
completion from another thread is posted through a wait-free inbox, whose slot
is reserved before the I/O starts.

## Calling Java

`nts bind` reads class files, from a jar or a directory, and writes one
declaration file per package:

```sh
nts bind --jar app.jar --package com.example --out types/
```

```ts
// GENERATED by `nts bind`. Do not edit.
declare module "java:com.example" {
  export class Catalog {
    /** @ntsJvm special com/example/Catalog.<init>:(Ljava/lang/String;)V */
    constructor(a0: string);
    /** @ntsJvm virtual com/example/Catalog.names:()Ljava/util/List;
     *  @ntsJvmKeeps none */
    names(): java.util.List<string> | null;
  }
}
```

```ts
import { Catalog } from "java:com.example";

const catalog = new Catalog("widgets");
const names = catalog.names();     // the Java list itself: no copy
```

- **Each member carries its exact JVM contract** in JSDoc: `@ntsJvm` gives the
  invocation (`static`, `virtual`, `interface`, `special`, `field`,
  `staticfield`) and `owner/Class.member:descriptor`; `@ntsJvmKeeps` gives the
  parameters the bytecode keeps (`none` when it keeps nothing). TypeScript
  picks the declaration and the compiler reads its contract, so there is no
  second binding file to drift.
- **Java's library** comes from generated preludes, global declarations of a
  curated member list for `java.*`.
- **Overloads** that collapse to one TypeScript signature are resolved by
  losslessness: `find(double)` keeps the plain name, and a narrowing one is
  reachable as `find$int`. Two equally lossless candidates are decided as
  `javac` decides them.
- **Nullability** is read from annotations in the class file; anything
  unannotated is `T | null`, and an overrides file (`--overrides`) says where
  that is wrong.
- **Java data stays Java:** a collection is the Java object, an `int[]` an
  `Int32Array`, a `long` a `bigint`, and a `ConstantValue` static is inlined
  without loading its class. Generics are surfaced; an inner class is
  constructed through its outer instance.
- **Classes extend Java classes:** `class Panel extends View` has `View` as its
  real superclass in the class file, and overrides its protected methods.
- **Callbacks:** a TypeScript function implements a Java callback interface. A
  callback on the calling thread may return a value; one arriving from a
  thread nts does not own is posted to the owner, and so must return nothing:
  a value-returning callback from a foreign thread is refused when bound.
- **Exceptions:** a Java exception never reaches a TypeScript `catch`. A bound
  call inside a `try` is refused (NTS1001), and outside one an exception ends
  the program. Every host error is decided to become a catchable `Error`
  carrying the host value ([errors](../language/errors.md#decisions)); J4
  proposes its shape, a `JavaError` with the throwable as `cause`.

## Java calling TypeScript

A Java program compiles against the emitted classes with `javac`:

```java
nts.gen.Session s = new nts.gen.Session();
double hits = s.bump();                                  // an exported class
String greeting = nts.gen.Program.greet("java");         // an exported function
java.util.Map<String, String> tags = nts.gen.Program.tags();
```

- An exported function is a static on `Program`; an exported class is a Java
  class whose instance methods forward to those statics. A `#private` field is
  package-private, so Java mutates only through the class's methods.
- A `number[]` is a `double[]`, with no copy or wrapper. A `Map` is a
  `java.util.Map` (the runtime's table implements it), keeps insertion order,
  and carries its generic types through the `Signature` attribute; a write from
  Java is a write to the program's own table.
- A `Uint32` parameter or result is a Java `long` holding the value, 0 to
  2^32 − 1. Inside the program it stays 32 bits in an `int`, and the entries
  compiled code calls with those bits are synthetic, like every other entry nts
  generates for its own calls: `javac` refuses a Java call to one.

## Android

- **API 29 and up.** The networking provider in
  `runtime/jvm/web-platform/android` needs API 29 for TLS's ALPN, and every
  Android fixture declares `minSdk: 29`. `d8` turns the class files into dex
  with no `invoke-custom`.
- **What the platform adds:** the Android provider supplies the web platform's
  networking and durable storage over Android's own APIs, and its R8 rules keep
  the surface compiled code reaches. ICU4J is bundled.
- **Where it has run:** compiled cases and the provider's suites run on ART
  by hand (`tooling/android/on-device.sh`), not in the gate; the full run
  checks that `d8` accepts what the backend emits.

## Strings, Unicode and numbers

Strings are `java.lang.String` and `StringBuilder`. Case mapping and character classes come from the JDK's tables,
which disagree with node's; the decided fix is nts's own tables (D4). The
TypeScript Intl over ICU4J in `runtime/ecmascript` exists, and `Intl` is not a
provided global. Number formatting is Grisu2, with a port of native's zmij
decided ([JVM and Wasm](../foundations/jvm-and-wasm.md#where-they-stand)).

## Open questions

- Weak references, `Math` against V8, and the shape of a Java exception:
  J1, J3 and J4 on [JVM and Wasm](../foundations/jvm-and-wasm.md#proposed-decisions).
- Host failures reaching a `catch`: [I-2](../open-questions.md#5-interop-and-hosts).

## Decisions

- Native comes first; the JVM is designed after it
  ([log](../records/notebooks/decisions-log.md#priorities-and-order)).
- The JVM uses nts's own Unicode tables (D4,
  [log](../records/notebooks/decisions-log.md#unicode-10-27)).
- test262 runs on every backend, the JVM included
  ([log](../records/notebooks/decisions-log.md#wasm-10-24-10-25)).
- A red that affects only the JVM does not block a landing; it is recorded in
  `tooling/conformance/jvm-declines.known` and fixed after
  ([log](../records/notebooks/decisions-log.md#priorities-and-order)).
- `SharedArrayBuffer` and `Atomics` on Android need API 33 (`VarHandle`), so
  they are refused below it; the Android floor stays API 29 (G19; 10-28,
  [log](../records/notebooks/decisions-log.md#builtins-and-globals-10-28)).
- ICU4J is bundled, never the device's, revisited only for mobile size (D-3;
  10-28,
  [log](../records/notebooks/decisions-log.md#products-toolchains-and-dependencies-10-28)).
- The JVM keeps the one async ordering contract every backend keeps, held by
  shared ordering fixtures (C-4; 10-28,
  [log](../records/notebooks/decisions-log.md#memory-concurrency-and-interop-10-28)).
- Map hashing is J2: the cached `String.hashCode` with the per-table tree
  fallback (X-4; 10-28,
  [log](../records/notebooks/decisions-log.md#debugging-security-and-versioning-10-28)).
  Not built.
- A program ships with a class archive that `nts build` writes from the
  classes it emitted, without running the program. The program uses it on the
  Java that built it and runs the same without it on any other (10-31,
  [log](../records/notebooks/decisions-log.md#jvm-class-archive-10-31)).
  Not built.
